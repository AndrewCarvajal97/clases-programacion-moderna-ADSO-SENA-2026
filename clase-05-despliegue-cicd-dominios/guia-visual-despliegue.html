A · Publicar en GitHub Pages

1

Sube tu portafolio a un repositorio

git add .
git commit -m "Portafolio listo para publicar"
git push
2

En el repo (web de GitHub): Settings → Pages

 GitHub · Settings › Pages
SourceDeploy from a branch
Branchmain / (root)Save
3

Espera ~1 min: tu sitio queda publicado

 GitHub Pages
✔ Your site is live at
https://tu-usuario.github.io/mi-portafolio
Error común: "404" al abrir → tu archivo principal debe llamarse index.html y estar en la raíz del repo. La primera vez puede tardar 1–2 minutos.

B · Publicar en Netlify (aún más fácil)

1

Entra a Netlify y arrastra tu carpeta

En "Sites" hay una zona que dice "arrastra tu carpeta aquí". Sueltas la carpeta del portafolio y ya está online. (También puedes conectar tu repo de GitHub para que se redeploye en cada push.)

 Netlify · Sites
⬆️ Arrastra la carpeta de tu sitio aquí para desplegar
2

Te da una URL al instante

Netlify
Published   https://tu-sitio.netlify.app

C · Conectar un dominio (apuntar el DNS)

Un dominio (tuweb.com) se conecta creando registros DNS que apuntan al host.

1

En el panel DNS de tu dominio, crea los registros

 DNS · tuweb.com
TipoNombreValor
A@185.199.108.153
CNAMEwwwtu-usuario.github.io

A apunta a una IP · CNAME apunta a otro nombre (alias). El host te da los valores exactos.

2

En el host, agrega tu dominio y activa HTTPS

"Custom domain" → escribes tuweb.com → esperas la propagación → 🔒 candado (HTTPS) automático.

D · CI/CD con GitHub Actions

1

Crea el archivo del workflow

En tu repo: .github/workflows/deploy.yml. Adáptalo de la plantilla oficial.

on:
  push: { branches: [main] }   # al subir a main
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/deploy-pages@v4   # publica en Pages
2

Míralo correr en la pestaña "Actions"

 GitHub · Actions
✅ Desplegar sitiohace 30ssuccess
✅ Desplegar sitiohace 5msuccess

Verde = publicó. Rojo = falló: abre la corrida, lee el paso rojo y búscalo en la doc.

Regla de oro: automatiza (CI/CD), prueba antes de publicar, guarda los secretos fuera del código y usa siempre HTTPS. Y sobre todo: lee la documentación oficial.
