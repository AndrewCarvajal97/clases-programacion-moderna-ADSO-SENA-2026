Concepto

¿Qué es HTML?

El esqueleto de toda página. No programa: marca qué es cada cosa.

📦 Lenguaje de marcado

HyperText Markup Language. Etiquetas que rotulan el contenido: "esto es un título", "esto es una imagen".

🍱 Analogía

Como los rótulos de una mudanza: no cambian lo de adentro, dicen qué es cada cosa para ordenarlo.

Anatomía

Partes de una etiqueta

<a href="pagina.html"> Clic aquí </a>

Apertura

Abre la etiqueta: <a>

Atributo = valor

Info extra. En HTML se llaman atributos (mucha gente les dice "propiedades").

Contenido

Lo que va entre apertura y cierre.

Cierre

</a> — con la barra /

Vocabulario preciso

Etiqueta ≠ Elemento

Etiqueta (tag)

La marca entre < >. Hay de apertura y de cierre.

<p>  …  </p>

Elemento

El conjunto completo: apertura + contenido + cierre. Es lo que existe en la página.

<p>Hola mundo</p>

La etiqueta es el rótulo; el elemento es la caja entera con lo que lleva dentro.

🔑 CLAVE

Etiquetas con cierre vs sin cierre

Con cierre (en par)
envuelven contenido: apertura + contenido + cierre
la mayoría
<p>Hola mundo</p>   <h1>Título</h1>   <div>…</div>
Sin cierre (vacías / void)
no envuelven nada; se cierran solas
img · br · hr · input · meta · link
<img src="foto.jpg" alt="Mi foto">   <br>  <hr>

💡 Regla: si una etiqueta envuelve contenido, lleva cierre. Si es un elemento "único" (imagen, salto, línea), no.

Estructura

El esqueleto de un documento

<!DOCTYPE html>
<html lang="es">
<head>
  <!-- info que NO se ve -->
  <meta charset="UTF-8">
  <title>Mi Portafolio</title>
</head>
<body>
  <!-- todo lo que SÍ se ve -->
</body>
</html>
<html> — toda la página
<head> — no se ve (config)
<body> — lo visible

💡 En VS Code escribe ! + Tab y sale solo.

🌳 EL DOM

El árbol de elementos (DOM)

El navegador convierte tu HTML en un árbol de elementos: el DOM. Cada elemento es un nodo con padres, hijos y hermanos.

<html>
<head> → <meta>, <title>
<body>
<header> → <h1>, <nav>
<main> → <section>…

JavaScript "agarra" estos nodos por el DOM (lo veremos en la Clase 04).

Relaciones en el árbol

Padres, hijos y hermanos

Padre / hijo

<ul> es el padre de sus <li> (hijos).

Hermanos

Los <li> entre sí son hermanos (mismo padre).

Anidar bien

Lo que abres último, ciérralo primero.

Los títulos tienen jerarquía: un solo <h1>, luego <h2>, <h3>… en orden. Importa para SEO y accesibilidad.

Metadatos

El <head>: metadatos 🏷️

Datos sobre la página que el navegador y Google leen (no se ven en pantalla).

<meta charset="UTF-8">

Para que los acentos y la ñ se vean bien.

<meta name="viewport"…>

Que se vea bien en celular (responsive).

<title>

El texto de la pestaña del navegador.

<meta name="description">

Resumen para Google (SEO).

El head a fondo

Los metadatos que importan

<meta charset="UTF-8">                  acentos y ñ
<meta name="viewport" …>           responsive (celular)
<meta name="description" …>        resumen para Google
<meta name="author" …>             autor
<meta name="theme-color" …>        color de la barra del navegador
<meta name="robots" content="index,follow"> indexar
<link rel="icon" href="favicon.ico"> iconito de la pestaña

💡 keywords ya casi no se usa (Google lo ignora).

🔎 SEO

Que Google y las redes te muestren bien

SEO básico

Un <title> claro, meta description, un solo <h1>, HTML semántico y alt en las imágenes.

Open Graph (redes)

Cómo se ve al compartir el link en WhatsApp/redes:

<meta property="og:title" …>
<meta property="og:image" …>
<meta property="og:description" …>

También: <link rel="canonical"> (la URL "oficial") y las Twitter Cards.

Atributos (propiedades)

Atributos: info extra de una etiqueta

Van en la apertura, como nombre="valor".

Comunes

href (enlace), src (fuente), alt (texto alterno de imagen).

class

Etiqueta reutilizable: la comparten muchos elementos. Se usa para estilos (CSS).

id

Único en toda la página. Sirve de ancla o para JavaScript.

<p class="destacado" id="intro">Hola</p>
Atributos especiales

Atributos booleanos (sí / no)

Con solo estar presentes ya valen "sí" (verdadero). No llevan valor.

<input required>                 obligatorio
<button disabled>               deshabilitado
<input type="checkbox" checked>  marcado
<input readonly>                 solo lectura
<div hidden>                     oculto

Otros: selected, autofocus, multiple.

Atributos que suman

rel, role, aria y más

  • rel — relación de un enlace: noopener, noreferrer, nofollow.
  • target — dónde abrir: _blank (otra pestaña).
  • download — descargar en vez de abrir.
  • title — tooltip al pasar el mouse.
  • role — el "rol" para accesibilidad (ARIA).
  • aria-label — nombre para lectores de pantalla.
  • alt — texto alterno de imágenes.
  • lang, data-* — idioma y datos propios.

Los role / aria-* ayudan a personas que usan lectores de pantalla.

Diferencia clave

class vs id 🎯

.class
se puede repetir en muchos elementos
para estilos (CSS)
Ej: todas las tarjetas con class="card" comparten el mismo estilo.
#id
único: solo un elemento lo tiene
anclas / JavaScript
Ej: id="contacto" para saltar a esa sección con href="#contacto".
Comentarios

Comentarios en HTML 💬

Notas para ti (u otro dev) que no se muestran en la página.

<!-- Esto es un comentario: el navegador lo ignora -->
<section> … </section> <!-- fin de la sección -->

Sirven para explicar partes del código o "apagar" algo temporalmente.

⭐ LO IMPORTANTE

¿Por qué HTML semántico?

😵 "Sopa de divs"
todo con <div>, sin significado
difícil de entender
<div class="header">…<div class="nav">…
✅ Semántico
etiquetas que dicen qué son
claro · SEO · accesible
<header> <nav> <main> <section> <footer>

Beneficios: Google te entiende (SEO), los lectores de pantalla ayudan a personas ciegas, y tu código se lee solo.

🧪 PRUÉBALO EN CLASE

El mismo CSS, dos resultados

🍝 Divididitis

<div>Mi Blog</div>
<div> … </div>

El CSS selecciona header, nav… → no aplica. Se ve plano.

✅ Semántico

<header>Mi Blog</header>
<main><article>…</article></main>

Las mismas reglas sí aplican. Se ve estilizado. ✨

👉 Con solo cambiar las etiquetas (¡mismo CSS!) cambia el estilo Y cómo lo interpreta el navegador (landmarks para Google y lectores de pantalla).

Para copiar y probar: codigo/ejemplo-semantico/ — abre divititis.html y semantico.html.

Vocabulario

Las etiquetas semánticas

<header>

El encabezado

<nav>

El menú

<main>

El contenido principal

<section>

Una sección

<article>

Un contenido independiente

<footer>

El pie de página

Cada etiqueta, su trabajo

Semántico: cuándo usar cuál

  • <header> — cabecera (de la página o de una sección).
  • <nav> — un menú de navegación.
  • <main> — el contenido principal (uno por página).
  • <section> — un bloque temático con su título.
  • <article> — contenido independiente (un post, una tarjeta de repo).
  • <aside> — contenido lateral/relacionado (barra, notas).
  • <footer> — pie (de la página o de una sección).
  • <figure>/<figcaption> — imagen con leyenda.

Otras útiles: <small> (letra pequeña/legal), <address> (contacto), <time> (fechas), <mark> (resaltar).

Imágenes, video y más 🎬

🖼️ Multimedia

img, video, audio, figure + figcaption (imagen con leyenda).

🔤 Texto y enlaces

a (enlace), strong/em (énfasis), ul/ol/li (listas), table (tablas).

⚠️ Sin internet, la imagen/video deben ser archivos locales en tu carpeta.

🔗 EL ENLACE <a>

Anchor y enlaces especiales

<a href="pagina.html">Ir</a>            otra página
<a href="#contacto">…</a>              salta a un id de ESTA página
<a href="mailto:hola@x.com">…          abre el correo
<a href="tel:+57300...">…             llamar (en el celular)
<a href="cv.pdf" download>…           descargar

⚠️ Al abrir en otra pestaña, usa siempre: target="_blank" rel="noopener noreferrer" — por seguridad y privacidad.

📐 FLUJO

Elementos de bloque vs en línea

Bloque (block)

Ocupan todo el ancho y empiezan en línea nueva.

divpsectionh1ul

En línea (inline)

Ocupan solo lo necesario, van seguidos en la misma línea.

spanastrongemimg

<div> = caja genérica de bloque; <span> = caja genérica en línea. (Con CSS puedes cambiarlo.)

Detalles importantes

Estilos por defecto y buenas costumbres

Estilos del navegador

Ya trae estilos: h1 grande y en negrita, listas con viñetas… El CSS los sobrescribe.

Minúsculas

Etiquetas en minúscula: <section>, no <SECTION>.

Evita deprecadas

<center>, <font> están obsoletas → eso se hace con CSS.

📝 FORMULARIOS

form, fieldset, label, input

<form>
  <fieldset>
    <legend>Datos</legend>
    <label for="correo">Correo</label>
    <input id="correo" type="email">
  </fieldset>
</form>

label con for=id del input: al hacer clic en el texto se activa el campo (accesibilidad). fieldset+legend agrupan.

Formularios · validaciones

Validar sin JavaScript

Atributos que validan

  • required — obligatorio
  • type="email" — formato correo
  • minlength, maxlength
  • min, max (números)
  • pattern="…" — expresión regular

datalist (sugerencias)

<input list="tec">
<datalist id="tec">
  <option>HTML</option>
</datalist>

El navegador muestra el error solo, sin escribir JS.

Enviar

input submit vs button

<button>

El moderno. Puede llevar HTML dentro (iconos). En un form, type="submit" por defecto.

<input type="submit">

El clásico. Solo texto, en el atributo value.

⚠️ type

<button type="button"> si NO quieres que envíe el formulario.

✨ INTERACTIVO NATIVO

details (acordeón) y dialog (modal)

<details>

<details>
  <summary>Ver más</summary>
  Contenido oculto…
</details>

Acordeón que abre/cierra sin JS.

<dialog>

Un modal nativo. La ventana ya es HTML; se abre con .showModal() desde JS.

Multimedia +

iframes y carga diferida

<iframe>

Incrusta otra página dentro (un mapa, un video de YouTube).

<iframe src="…"></iframe>

loading="lazy"

Carga la imagen/iframe solo al acercarse → página más rápida.

<img loading="lazy" …>
Listas

ol y ul a fondo

<ul> — sin orden

Con viñetas. Para cosas donde el orden no importa.

<ol> — ordenada

Numerada. Atributos: type="A", start="3", reversed.

Dentro de ambas: <li> (list item).
