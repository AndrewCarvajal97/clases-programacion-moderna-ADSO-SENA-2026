Conectar

Cómo se conecta JS al HTML

En un archivo aparte script.js, enlazado antes de cerrar el <body>:

  </main>
  <!-- el script va al final para que el HTML ya exista -->
  <script src="script.js"></script>
</body>

💡 Mismo principio que el CSS: en un archivo aparte, no mezclado en el HTML.

📌 3 FORMAS

Tres maneras de incluir JavaScript

1. Inline (atributo) ❌

<button onclick="alert('Hola')">
  Clic
</button>

Rápido, pero mezcla HTML y JS y no se reutiliza. Evítalo.

2. Interno (<script>)

<script>
  const x = 1;
</script>

JS dentro del HTML. Así trabajan los frameworks (Vue, Astro): el JS del componente vive junto a su plantilla.

3. Externo (archivo) ✅

<script src="script.js">
</script>

En un .js aparte. Lo recomendado: ordenado, reutilizable y cacheable.

Con type="module" el externo además permite import/export (lo veremos en Nivel PRO).

🗂️ OBJETOS

Objetos: diccionarios de datos

Un objeto guarda varios datos con etiqueta (pares clave: valor), como una ficha o un formulario. Tu datos.json es exactamente esto.

const persona = {
  nombre: "Ana",
  edad: 20,
  saludar() { return `Hola, soy ${this.nombre}`; }
};

persona.nombre;      // "Ana"  (con punto)
persona["edad"];     // 20     (con corchetes)

Array vs Objeto

Array [] = lista ordenada. Objeto {} = datos con nombre.

Acceso

.clave o ["clave"].

⚙️ LO MÁS IMPORTANTE

Funciones: bloques reutilizables

function saludar(nombre) { return "Hola " + nombre; }

Una función es una receta con nombre: la escribes una vez y la reutilizas cuantas veces quieras. Evita repetir código.

🏹 ARROW

Funciones flecha (=>)

// función de siempre
function sumar(a, b) { return a + b; }

// función flecha: lo mismo, más corto
const sumar = (a, b) => a + b;   // una línea → return implícito

// un solo parámetro: sin paréntesis
const doble = n => n * 2;

Son las que usas en addEventListener("click", () => …) y en .map(). Además, this se comporta de forma predecible.

Tomar decisiones

Condicionales: if / else

if (edad >= 18) {
  console.log("Es mayor de edad");
} else {
  console.log("Es menor");
}

Comparaciones: === (igual), !== (distinto), >, <. Ojo: JS distingue mayúsculas.

🔀 DECISIONES CORTAS

&& · || · ?: (el if corto)

const esMayor = edad >= 18;

const entra  = tieneBoleto && esMayor;      // Y: los DOS verdaderos
const nombre = apodo || "invitado";         // O: el primero que "sirva"
const texto  = esMayor ? "Adulto" : "Menor";  // ternario = if/else corto

&& Y

Verdadero si ambos lo son.

|| O

El primero que no sea "vacío".

? :

condición ? sí : no

🛡️ A PRUEBA DE FALLOS

?? (nullish) y ?. (opcional)

// ?? usa la derecha SOLO si la izquierda es null o undefined
const puntos = usuario.puntos ?? 0;   // si puntos es 0, RESPETA el 0

// ?. no explota si algo intermedio no existe
const ciudad = usuario.direccion?.ciudad; // undefined, no error 💥

⚠️ ?? vs ||

|| descarta 0, "" y false (los toma como "vacío"). ?? solo descarta null/undefined. Para números y textos, ?? es más seguro.

🧹 BUENA PRÁCTICA

Negación temprana: adiós a los if anidados

🪆 Anidado
un if dentro de otro dentro de otro…
forma de flecha →
function saludar(usuario) {
  if (usuario) {
    if (usuario.activo) {
      console.log("Hola " + usuario.nombre);
    }
  }
}
✅ Cláusulas de guarda
niega y sal temprano (return)
plano y legible
function saludar(usuario) {
  if (!usuario) return;          // no hay usuario → salgo
  if (!usuario.activo) return;   // inactivo → salgo

  console.log("Hola " + usuario.nombre); // el caso bueno, sin sangría
}

Descarta primero lo malo con ! (negación) y return. Lo importante queda al final, sin anidar. Es justo lo que hace Contacto.js: if (error) return;

Repetir · listas

Bucles y arreglos

Array (lista)

const skills = ["HTML", "CSS", "JS"];

Recorrerlo (for)

for (const s of skills) {
  console.log(s);
}

Un array guarda varias cosas; un bucle las recorre una por una.

📦 DESEMPACAR

Desestructuración

Saca campos de un objeto (o de un array) a variables, de un solo golpe. Como desempacar una maleta y poner cada cosa en su sitio, ya etiquetada.

De objetos

const persona = { nombre: "Ana", edad: 20 };
const { nombre, edad } = persona;
// nombre = "Ana", edad = 20

De arrays (por posición)

const colores = ["rojo", "verde"];
const [primero, segundo] = colores;
// primero = "rojo"

Ya la usaste: const { default: confetti } = await import(…) en tu portafolio.

✨ EL OPERADOR ...

Spread y rest: los tres puntos (...)

Spread: "esparce"

const base = ["html", "css"];
const skills = [...base, "js"];   // copia + agrega

const copia = { ...persona, edad: 21 }; // copia y cambia

Rest: "junta"

// junta varios argumentos en un array
function sumar(...numeros) {
  return numeros.reduce((a, b) => a + b, 0);
}
sumar(1, 2, 3); // 6

Sirve para copiar/combinar sin dañar el original. Lo usas en Contacto.js: { access_key, ...datos }.

JS toca el HTML

El DOM: agarrar elementos

El DOM es tu HTML visto desde JS. Con querySelector agarras un elemento:

// por id (#) o por clase (.)
const titulo = document.querySelector("#titulo");
titulo.textContent = "¡Cambiado desde JS!";

Puedes cambiar texto, estilos o clases de cualquier elemento.

🖱️ INTERACCIÓN

Eventos: reaccionar al usuario

const boton = document.querySelector("#btn-tema");

// "cuando hagan clic, ejecuta esta función"
boton.addEventListener("click", () => {
  document.body.classList.toggle("oscuro");
});

addEventListener = "escucha" un evento (click, submit, teclado…) y responde.

🍝 vs ✨ CLAVE

Código espagueti vs código limpio

🍝 Espagueti
todo suelto, repetido, enredado
difícil de mantener
// copiado y pegado, sin nombre, global
b1.onclick = ()=>{body.style.background="#000";body.style.color="#fff"}
b2.onclick = ()=>{body.style.background="#000";body.style.color="#fff"
✨ Limpio (funcional)
una función con nombre, reutilizable
fácil de cambiar
function activarModoOscuro() {
  document.body.classList.toggle("oscuro");
}
boton.addEventListener("click", activarModoOscuro);

Si cambia la lógica, en el limpio la tocas en un solo lugar. En el espagueti, en veinte.

Buenas prácticas

Cómo escribir código limpio

✅ Sí

  • Nombres claros: activarModoOscuro, no x.
  • Funciones pequeñas que hacen una cosa.
  • const por defecto.
  • No repetir (DRY): si copias-pegas, hazlo función.

❌ No

  • Variables globales sueltas por todos lados.
  • Copiar-pegar el mismo bloque muchas veces.
  • Nombres como a, dato1, cosa.
  • Todo mezclado en el HTML.

Comenta el por qué, no el qué (el código ya dice el qué).

🕰️ JS DE AYER vs DE HOY

Prácticas modernas vs antiguas

JavaScript cambió mucho (sobre todo desde ES6, 2015). En tutoriales viejos verás código que funciona… pero que hoy se escribe mejor. Ejemplo estrella: seleccionar del DOM.

👴 Antes
un método distinto para cada caso
verboso
document.getElementById("titulo");
document.getElementsByClassName("card");
document.getElementsByTagName("p");
✨ Ahora
UN método, con selectores CSS
unificado
document.querySelector("#titulo");   // uno (#id, .clase, etiqueta)
document.querySelectorAll(".card"); // todos (y tiene forEach)

querySelector usa los mismos selectores que CSS: no memorizas 3 métodos, usas uno. (getElementById no está "mal", pero querySelector lo unifica todo.)

La chuleta

De lo viejo a lo moderno

👴 Antiguo

var nombre = "Ana";
"Hola " + nombre + "!";
btn.onclick = function(){…};
el.className += " activo";

for(var i=0;i<a.length;i++)

✨ Moderno (ES6+)

el.classList.add("activo");
if (a === b) …            // estricto

Todo esto ya lo usas en tu portafolio. No es "moda": es más corto, más seguro y más fácil de leer.

🌐 PEDIR DATOS

De callbacks y jQuery… a fetch + async

👴 Antes

// XMLHttpRequest o jQuery
$.ajax({ url, success: function(d){
  hacerAlgo(d, function(){ … }); // callbacks anidados 😵
}});

✨ Ahora

async function cargar() {
  const res = await fetch(url);
  const datos = await res.json();
}

Hoy casi no necesitas jQuery: lo que antes resolvía ($(".x"), ajax, animaciones) ya lo hace el navegador nativo (querySelector, fetch, CSS). Menos peso, menos dependencias.

🌐 PEDIR DATOS A INTERNET

fetch: peticiones HTTP

Con fetch tu JS le pide datos a una API (otro servidor) y los usa en la página.

// async/await: espera la respuesta de internet sin congelar la página
async function cargarPerfil() {
  const res = await fetch("https://api.github.com/users/octocat");
  const datos = await res.json();
  console.log(datos.name, datos.public_repos);
}

También existe axios (una librería que hace lo mismo, más cómodo). ⚠️ Necesita internet.

🎬 LIBRERÍA

Animaciones modernas: anime.js

const { default: anime } = await import("…animejs…");

anime({
  targets: ".hero .reveal",   // qué animar
  translateY: [24, 0],       // de abajo → a su sitio
  opacity: [0, 1],
  delay: anime.stagger(90),  // en cascada ✨
  easing: "easeOutCubic"
});

Ligera y fácil. stagger anima una lista en cascada con una línea. Ya está en tu portafolio.

🚀 LIBRERÍA PRO

GSAP: timelines de nivel producción

// animar DESDE un estado hasta el actual
gsap.from(".hero__title", { y: 40, opacity: 0, duration: 1 });

// una TIMELINE: animaciones en secuencia
const tl = gsap.timeline();
tl.from(".eyebrow", { opacity: 0, y: 20 })
  .from(".hero__title", { opacity: 0, y: 30 }, "-=0.3");

El estándar en portafolios "wow". Tiene ScrollTrigger (animar según el scroll). Regla: la animación decora, no estorba. Respeta prefers-reduced-motion.

🍝 EL PROBLEMA

Un solo script.js de 400 líneas

❌ Todo mezclado

  • El tema, el fetch, el formulario… todo junto.
  • Para cambiar algo, buceas entre lo demás.
  • Un nombre repetido y se rompe todo.

✅ La solución

  • Una clase por tema (POO).
  • Un archivo por responsabilidad (módulos).
  • El contenido, aparte en un JSON.

Analogía: no necesitas un cajón más grande; necesitas cajones etiquetados.

🧬 POO

Clases: moldes de galletas

class Perro {
  constructor(nombre) {   // al crear el objeto
    this.nombre = nombre; // propiedad
  }
  ladrar() {              // método
    console.log(`${this.nombre} ¡Guau!`);
  }
}
const firu = new Perro("Firulais");
firu.ladrar();  // Firulais ¡Guau!

class = molde

Qué datos guarda y qué sabe hacer.

new Perro() = objeto

Una galleta hecha con el molde.

this

"este objeto en particular".

🐙 API REAL

Tus datos reales de GitHub

export class GitHubAPI {
  constructor(usuario) { this.usuario = usuario; }
  async obtenerPerfil() {
    const res = await fetch(`https://api.github.com/users/${this.usuario}`);
    return res.json();  // avatar, repos, followers…
  }
}

Trae avatar_url, public_repos, followers y tus repos. ⚠️ Sin token: ~60 peticiones/hora (suficiente). Nunca pongas tokens en el navegador.

💼 SÉ HONESTO

LinkedIn no tiene API libre

❌ No se puede

A diferencia de GitHub, LinkedIn protege sus datos. No hay fetch a tu perfil. "Rasparlo" viola sus términos y se rompe.

✅ Lo que SÍ se hace

  • Un botón/enlace a tu perfil (desde el JSON).
  • El badge oficial de LinkedIn (insignia pública).
  • Datos que tú escribes en datos.json.

Lección dev: antes de programar contra un servicio, revisa si tiene API y si está permitida.

✉️ FORMULARIO REAL

Que el formulario envíe correos

Un form HTML no envía solo: usamos un servicio gratuito de intermediario.

Web3Forms ⭐

Sin cuenta: solo un access key. 1 paso. El del curso.

Formspree

Cuenta gratis + un endpoint. Panel de mensajes.

EmailJS

Plantillas de correo. Más potente, más pasos.

await fetch("https://api.web3forms.com/submit", {
  method: "POST",
  body: JSON.stringify({ access_key: "TU_KEY", nombre, correo, mensaje })
});

Siempre valida antes (nombre, @, largo). Las keys de form sí van al frontend; un token secreto no.

Checklist profesional
