📡 PROTOCOLOS

¿Qué es un protocolo?

Un conjunto de reglas acordadas para comunicarse — como el "aló" y el "chao" de una llamada.

En la web hay tres que debes conocer:

📩 HTTP

Pregunta y respuesta

📻 SSE

El servidor transmite

📞 WebSocket

Conexión viva

Protocolo 1 · 📩

HTTP — pregunta y respuesta

Cliente
Servidor
→ te pido
Cliente
Servidor
← te respondo, y cierro

Cada cosa es una petición nueva. Métodos: GET POST

Ejemplos: cargar una página, pedir datos a una API.

Protocolo 2 · 📞

WebSocket — conexión viva

Cliente
Servidor

La conexión queda abierta en los dos sentidos. El servidor manda cosas sin que el cliente pida.

📞 Como una llamada

Que no se cuelga.

⚡ Tiempo real

Chat, juegos, colaboración en vivo. Lo usaremos con Socket.IO.

Protocolo 3 · 📻

SSE — el servidor te va contando

Cliente
Servidor
← flujo (una sola vía)

El servidor transmite un flujo de mensajes; el cliente solo escucha.

📻 Como oír la radio. Ideal para notificaciones, feeds en vivo y barras de progreso. Más simple que WebSocket.

🔑 SSH · PASO A PASO

Conectarte a GitHub con SSH

1 Crea tu llave (una vez)

ssh-keygen -t ed25519 -C "tu-correo"

Presiona Enter en todo (sin contraseña está bien para empezar).

2 Copia la llave PÚBLICA

cat ~/.ssh/id_ed25519.pub

Copia todo (empieza con ssh-ed25519).

3 Pégala en GitHub

Settings → SSH and GPG keys → New SSH key → pega y guarda.

4 Prueba la conexión

ssh -T git@github.com

Debe decir: "Hi usuario! You've successfully authenticated".

Listo: ya usas URLs git@github.com:... sin escribir contraseña cada vez. 🎉

Automatización

GitHub Actions 🤖

Un robot que, cuando haces push, prueba tu código y lo despliega solo. Eso es CI/CD.

# .github/workflows/deploy.yml
on: [push]           # cuando subo código...
jobs:
  build:
    steps:
      - run: pnpm install && pnpm test   # ...prueba y publica

No hace falta dominarlo hoy: lo veremos a fondo más adelante.
